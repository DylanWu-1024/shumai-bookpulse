怎么拿到微信读书的 Cookie

书脉 BookPulse · 图文版操作说明 · 只需要做一次，通常能管数周到数月

Windows / Mac 通用 Chrome / Edge / 新版 Edge 内核浏览器
📌 更新（2026-10-03）：这份教程现在用不上了 —— AI 大纲已经不需要登录。

我用真实浏览器把请求原样抓出来复现后确认：程序之前调的 /web/book/outline/inner 是个恒返回 403 的接口（带着有效 Cookie 也一样）， 而浏览器真正调用的是 POST /web/book/outline —— 它不需要登录。

实测不带任何 Cookie：《短线交易秘诀》122 章 / 2035 条、《活着》10 章 / 233 条， 全部 200。现在选一本书直接点「获取 AI 大纲」就行。

下面这份教程保留着，万一以后有别的接口需要登录，还能照着做。
先说清楚：Cookie 是什么、为什么要它？
Cookie 是浏览器登录后拿到的一小段「通行证」。带上它，微信读书才知道「是你本人」。 抓热门划线不需要登录，所以不需要 Cookie；但 AI 大纲的正文接口必须登录才给， 不带就返回 403。
它只存在你自己电脑的 data/settings.json 里，只用于 AI 大纲这一项， 不会上传到任何地方。不想要了，把设置里那个框清空即可。

方法 A（最推荐）：从 Network 里复制 Cookie 那一行

这是最可靠的办法，因为它就是浏览器真正发出去的东西，一个都不会漏。

1
打开微信读书并确认已登录：https://weread.qq.com/
（也可以直接在程序里点 设置 → 微信读书登录 → 「打开微信读书（去登录）」）
2
按 F12 打开开发者工具，切到顶部标签 Network / 网络。
3
刷新一下页面，让列表里出现请求；列表里会刷出很多条目。
4
在列表里随便点一条（点第一条也行）。右侧会展开这个请求的详情。
5
在右侧找到 Request Headers / 请求标头 分组， 里面有一行叫 Cookie。
如果没看到这一行，点一下该分组的 「展开」/ Raw 按钮。
6
在 Cookie 那一行上点右键 → 选「Copy value / 复制值」。
复制到的内容会长这样（一长串 名字=值）：
gid=1a0d0c9d…; wr_gid=236719037; wr_localvid=0af32fa0…;
wr_name=DylanWu; wr_vid=931802091; wr_rt=o2uxBws…;
wr_skey=H2uiy1ga; wr_fp=828482527
7
回到书脉 → 设置 → 微信读书登录 → 点 「从剪贴板粘贴」。
8
看下面的提示：应当出现 「识别到关键字段：wr_vid / wr_skey / …」。看到 wr_vid 和 wr_skey 就说明复制对了。

方法 B（一键最省事）：Copy as cURL

比方法 A 还少几步，程序同样认得这一整段。

  1. 同方法 A 的第 1~4 步：F12 → Network → 刷新 → 点一条请求
  2. 在那条请求上点右键 → Copy（复制） → Copy as cURL (bash)
  3. 回程序 → 设置 → 微信读书登录 → 「从剪贴板粘贴」

粘贴进去的会是一大段以 curl 开头的文字，这是正常的 —— 程序会自动只挑出 Cookie 那一行，其余的参数全部忽略。

方法 C（备选）：Application 面板

这个位置的 Cookie 用鼠标框选多行再复制也能用，但我把它排在后面，原因见下方红框。

  1. F12 → 顶部切到 Application / 应用程序
  2. 左侧 Storage → Cookies → 点开 https://weread.qq.com
  3. 在表格里把 wr_vid、wr_skey、wr_rt、wr_localvid、 wr_gid、wr_fp 这几行选中 → 复制
  4. 回程序粘贴。表格里带过来的「域 / 过期时间 / 大小」等多余列会被自动丢掉
为什么不推荐在这里一行一行抄？
表格里字段很多（还有 _ga、_clck 这些和登录无关的）， 手抄容易漏掉或抄错 wr_skey、wr_vid 的字符 —— 一旦错一个字符， 接口就会拒绝，而错误信息只有一句 403，很难排查。

❌ 不要用 copy(document.cookie)

在 Console 里执行 copy(document.cookie) 看起来能拿到东西，但可能缺关键的：
标了 HttpOnly 的 Cookie，JavaScript 根本读不到 —— 而 wr_skey 常常就是其中之一。 结果就是「看着复制到一大串、程序也说识别到了字段，但一测就 403」。
所以请用方法 A 或 B。这一条我上一版说明里写错了，这里更正。

粘完怎么确认弄对了

你看到的说明下一步
提示「识别到关键字段：wr_vid / wr_skey / …」 格式正确，程序认出了登录凭据 点「测试连接」
提示「没识别到 Cookie 关键字段」 多半是复制到了别的地方（比如响应头 Response Headers，那里没有 Cookie） 回到方法 A 第 5 步，确认是 Request Headers
测试后提示「章节列表拿到了，但正文没取到」 Cookie 有效、服务端认出了你的账号，但正文接口还拒绝（程序侧我仍在排查） 先用「在微信读书打开大纲」在浏览器看

常见问题

为什么热门划线不用 Cookie，AI 大纲就要？

因为它们是两个不同的接口。热门划线是公开数据，任何人（含未登录）都能取； AI 大纲正文被微信读书放在登录墙后面，不带通行证直接 403。 就像一个网站，公开页面谁都能看，但「我的笔记」得先登录。

Cookie 会过期吗？

会，但不是按天算。多数情况下能用数周到数月。等到程序开始提示登录失效， 按上面的方法再复制一次即可（一两分钟的事）。

是不是每本书都有 AI 大纲？

不是。取决于微信读书有没有为这本书生成。程序会明确告诉你： 点「获取」后，如果这本书一章都没有要点，会直接提示 「微信读书没有为这本书生成 AI 大纲」。
另外注意：章节列表是免登录就能拿到的 —— 也就是「这本书有几章、哪几章带 AI 要点」 不看登录也一清二楚，只有要点正文才需要登录。

换了浏览器 / 清了浏览器数据怎么办？

Cookie 跟着浏览器走。换了浏览器或清了站点数据，就按上面的方法重新复制一次。

安全吗？

Cookie 存在你自己电脑上，只用于 AI 大纲接口；程序抓热门划线时从不携带任何登录信息。 所有源码在 GitHub 上公开可查，可以自己搜 Cookie 确认它只出现在登录相关的那几行。 不放心就随时把设置里的框清空。
