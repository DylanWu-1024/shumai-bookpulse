书脉

把微信读书里「大家划过的句子」变成你自己的知识 —— 抓取、沉淀、让 AI 帮你整理。

一、怎么开始（三步）

  1. 双击 书脉.exe —— 不需要安装任何东西，不需要 Python。
    （单文件版首次打开会先解压，可能要等 2~3 秒，属正常现象）
  2. 在「搜索下载」页输入书名 → 点搜索 → 在候选列表里挑一本 → 点「抓取选中这本书的热门划线」。
  3. 看结果 → 点「导出」，文件会出现在程序旁边的 exports 文件夹里。
为什么候选列表里会显示评分？
每本书后面那串「神作 92.0% · 21.4万人评价 · 2537人在读」是微信读书公开的推荐数据 —— 同名书一眼就能看出哪本更值得读，不用点进去猜。

二、七个页面各能干什么

页面用途
搜索下载搜书 → 抓热门划线 → 预览 → 导出。可按章节看，也能一键让 AI 整理成笔记。
批量队列书名一行一个，排队抓取。默认每本之间随机停 2~4 秒，这个间隔别调到 0。
本地书库抓过的书自动存进来，可以离线秒开（不联网）、看热度变化、加入关注。
洞察台跨书检索 + 主题聚合 + 关注推送，全部读本地数据，不发一次网络请求。
导出记录浏览导出过的文件、双击打开、删除（走回收站，可还原）。
AI 大纲每本书的章节 AI 要点，单独一页浏览、复制、导出。这一项需要先在设置里填一次 Cookie。
设置外观、语言、导出规则、AI 助手、微信读书登录、飞书推送。

三、进阶玩法

🤖 一键 AI 整理抓完书点「AI 整理」，选一个模板（精华提炼 / 主题对比 / 行动清单 / 关键词），AI 直接给你整理好的笔记。需要先在设置里填一个 API Key。
📊 按章节看哪几章最戳人，一眼看热度条。展开还能看到同一段落里其他读者还在关注什么。
🔍 跨书检索搜「复利」，列出你所有书里跟它有关的高热划线，按共鸣人数排序。
🧩 主题聚合勾选 2~5 本同主题的书，让 AI 产出「这些书在同一个问题上各自怎么说」。
📈 热度趋势同一本书抓两次以上，就能看到哪句话正在越来越多人划线（折线图）。
🔔 关注推送把书加入关注，程序会自动检查新晋热门划线，还能推一条卡片到飞书群。
📋 一键复制不想落文件时，点「复制」直接拿走 Markdown 或纯文本；双击表格里任意一行，就复制那一句。
📄 导入书单批量页支持从 txt / csv 导入书名，也可以把文件直接拖进窗口；书库页有筛选框，书多了也好找。
🧠 思维导图把一本书的划线画成脑图，可导出 PNG / SVG；也能导出大纲（Markdown / OPML）直接导入 XMind、幕布。
🔗 跨书去重合并把不同书里说同一件事的句子归到一起 —— 被反复强调的道理才最值得记住。本地算，不外传。
🎯 专注模式按 Ctrl+Shift+F 一键隐藏侧栏和顶栏，屏幕只剩正文。
⚡ 全文索引书库用 FTS5 建全文索引，几百本书里搜一个词也是毫秒级。
🖱 右键快捷操作在结果表格里右键 → 复制这一句 / 复制本章 / 复制整本；双击任意一行直接复制那句话。
📚 AI 大纲微信读书给不少书生成了「每章要点」。侧栏点「AI 大纲」→ 选书 → 获取，就能看到每一章的要点，可复制可导出。需要先在 设置 → 微信读书登录 里填一次 Cookie（怎么拿见常见问题）。
📊 排序切换结果那一行的「排序」可以选按热度或按章节，切了表格立刻重排，不用另开窗口。导出的顺序也跟着走。
📖 跳到微信读书抓完一本书，点「在微信读书阅读」直接进入可阅读的正文界面（不是只有简介的详情页），能点选区域、划词。浏览器的登录状态还在，接着读就行。想看书架详情页，在那按钮上右键。

导出格式怎么选

格式什么时候用
HTML 网页自己看。页面顶部有「复制 Markdown」按钮，方便贴给别人
Markdown喂给 AI（DeepSeek / ChatGPT 等）最顺，序号和标题结构它最熟
纯文本万能兜底，粘哪儿都不会乱
CSV要用 Excel 排序、筛选、做透视表时
JSON给程序用
Word（.docx）要接着编辑、写读书报告、交作业时
PDF打印、归档、发给别人但不想被改
EPUB导入 Kindle / 微信读书 / Apple Books，当成一本小书来读
分享版发给朋友看。手机自适应、按章节分组，在微信/飞书里发出去有预览

导出模板可以自己调

在 设置 → 导出模板 里可以改：正文字号、是否带章节、是否带序号、标题颜色。 调完对 Word / PDF / EPUB / 网页 / 分享版 / Markdown 全部生效 —— 不用每个格式单独设一遍。

在设置 → 抓取与导出 → 导出格式里可以多选，之后导出下拉选「按设置（多格式）」就会一次生成多份。

导出的文件里默认不含「N 人划线」。
文件里只有句子和章节 —— 发给别人看的是内容，不是平台数据。想看热度排序，在软件的结果表格里看就行。
需要还原成带人数的版本，去 设置 → 抓取与导出 → 导出内容里带上「N 人划线」 打开开关即可。

想按心情换换样子

设置页可以换 4 套主色（蓝紫暮光 / 青柠薄荷 / 蜜桃气泡 / 深海蔚蓝）× 浅色 / 深色 / 跟随系统，圆角大小也能拖。换完立刻生效，不用重启。

五、常见问题

Windows 提示「已保护你的电脑」/「未知发布者」怎么办？
这是所有个人开发的小工具都会遇到的提示（因为没有买代码签名证书）。
点 更多信息 → 仍要运行 即可。
「AI 大纲」为什么要填 Cookie？
微信读书的 AI 大纲正文接口必须带登录态才会返回（不带会直接 403）。 所以设置里有一项「微信读书登录」：把浏览器的 Cookie 粘进去即可。 只有这一项功能会带上它 —— 抓热门划线始终不带 Cookie，Cookie 也只存在你自己电脑上。

怎么把 Cookie 交给程序（一次搞定，之后长期有效，通常管数周到数月）：
📘 嫌下面步骤多？看这份带图详解：同目录下的《如何获取Cookie.html》，双击用浏览器打开即可
  1. 在程序里点 设置 → 微信读书登录 → 「打开微信读书（去登录）」， 用它打开的页面登录你的微信读书账号（这一步只是登录，不是把密码交给程序）。
  2. 在那个网页上按 F12，切到 Network / 网络 标签，刷新一下页面， 然后随便点其中一条请求。
  3. 在右侧找到 Request Headers / 请求标头 里的 Cookie 那一行 （如果没看到，点一下 「展开」/ Raw）。 在那一行上右键 → Copy value（复制值）。
  4. 回到程序，点 「从剪贴板粘贴」 → 点 「测试连接」。 程序会显示识别到哪些字段（正常应有 wr_vid 和 wr_skey）， 并自动拿一本有要点的书实测一次，直接告诉你成不成。
为什么推荐从 Network 复制，而不是从 Application 面板拼？
Application 面板里那些 Cookie 标了 HttpOnly 的，JavaScript 读不到 （比如 wr_skey 常常就是），所以用 copy(document.cookie) 这类办法可能拿不全； 而 Network 里的请求头是浏览器真正发出去的完整内容，最保险。

另一个同样省事的办法：在 Network 里右键那条请求 → Copy → Copy as cURL，然后回程序点「从剪贴板粘贴」。程序也认这一整段。

程序认得这些形态，你复制成什么样都行： 标准串（名字=值; 名字=值）、整段 Request Headers、 Application 表格（Tab 分隔的多行）、名字: 值、 Copy as cURL、插件导出的 JSON。Path、Domain、Secure 这些属性会自动丢掉。
万一复制错了地方（比如粘成了响应头），程序会直接提示「没识别到关键字段」， 不会拿着错东西去请求。
为什么不能像 QQ 那样在程序里扫码？
因为微信读书的二维码是微信官方生成的，扫码后微信把登录凭据回调给 weread.qq.com —— 这个回调只会送到浏览器，我们的程序在纯网络层面收不到它， 所以扫码这条路必须内嵌一整个浏览器内核才行（会让程序体积从 47MB 涨到约 150MB）。 目前先用「粘贴一次 Cookie」的方式，体积零增长、有效期通常数周到数月。

安全性：Cookie 只存在你自己电脑的 data/settings.json 里， 只用于 AI 大纲这一项功能；抓热门划线始终不带任何登录信息。 不想要了，把那个框清空即可。

还有一点要有预期：不是每本书都有 AI 大纲。《活着》整本 13 章一章都没有； 《短线交易秘诀》125 章里有 122 章带要点 —— 程序会直接告诉你这本书有没有。

关于风控，我要说清楚

  • 程序只用公开接口读公开数据，而且不携带任何登录信息（不发 Cookie）。服务端拿不到你的账号身份，技术上无法归因到个人账号。
  • 批量抓取默认每本之间随机停 2~4 秒，请不要调成 0 —— 那是把风险从「几乎为零」变成「有可能」。
  • 它仍然属于「非官方接口」。建议：不要一次刷几百本，也不要把抓下来的内容公开传播。
  • 想更稳妥，就用「批量队列」慢慢跑，一次十几本，中间去干点别的。

数据存在哪里？

  • 导出文件：程序旁边的 exports 文件夹（可以在设置里改到别处）。
  • 本地书库：data\hotmarks.db（一个 SQLite 文件，删掉就等于清空书库）。
  • 设置：data\settings.json，包括 API Key —— 只存在你本机，不会上传到任何地方。

抓取变慢了 / 老失败怎么办？

先点「网络自检」。打开 设置 → 网络，点一下 网络自检 按钮，它会分别实测 「直连」「跟随系统代理」两条路的真实耗时，直接告诉你哪条快、哪条通。

为什么会有这个问题？如果你装过 Clash / v2ray 这类代理软件，Windows 会一直留着代理配置， 即使软件已经关掉、端口已经没人监听。程序一旦跟着这个配置走，每次请求都会先去撞那个死端口， 失败后再重试 3 次，几分钟就过去了 —— 表现就是「什么都慢」。
而微信读书是国内站点，直连本来只要零点几秒。

怎么修：把 连接方式 选成 直连（推荐）（这也是默认值）。 只有当你确实需要走代理时，才选「跟随系统代理」或「自定义代理地址」。

其他可以让抓取更稳的设置：把超时调到 40~60 秒、重试次数调到 5 次。 程序默认就会指数退避重试（0.8 秒 → 1.6 秒 → 3.2 秒，带随机抖动），所以偶尔抽风不用管它。

这项设置同时作用于：抓取微信读书 + 调用 AI 接口 + 推送飞书。 也就是说，如果你用 OpenAI 这类需要代理的模型，就把连接方式选「跟随系统代理」。

API Key 怎么填？

打开 设置 → AI 助手，选一个提供商（推荐 DeepSeek，便宜且中文好），点「获取 Key」跳到官网申请，粘贴回来，再点「测试连接」确认能通。

不想用云端也行：装个本地 Ollama，提供商选「本地 Ollama」，不花钱、不联网。
