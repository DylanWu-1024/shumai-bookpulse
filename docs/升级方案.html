2五条升级主线

2.1 交互形态：脚本 → 软件 → 免安装 exe

  • 现在：双击 .bat 弹黑框，靠问答式输入。
  • 已升级：桌面工作台，左侧导航 + 表格 + 进度条 + 深色日志区，全程可视可控。
  • 下一步：打包成单个 exe，丢到桌面双击就用，不装 Python、不进命令行。

2.2 批量能力：单本 → 队列 → 定时订阅

  • 现在：一次一本。
  • 已升级：一行一个书名贴进去，顺序抓取，两本之间随机等 2~4 秒，随时可中止，单本失败不影响后面的。
  • 下一步：书单导入（粘贴一整份书单）、定时增量（每天自动抓一次，只告诉你「今天多了哪几条热门划线」）。

2.3 数据形态：文本 → 本地知识库

  • 现在：一堆散落的文件，重复抓同一本书要重新联网。
  • 下一步：引入 SQLite 单文件数据库——
    • 同一本书抓过一次就入库，之后离线可查，不再重复请求（额外降低风控暴露面）；
    • 支持热度变化追踪：三天前这条 300 人划线，今天 500 人，一眼看出哪句话正在被越来越多人标记；
    • 支持跨书检索：搜「复利」时，把十本书里所有含这个词的高热划线一次列出来。

2.4 智能整理：导出 → LLM 闭环

  • 现在：导出的 Markdown 你自己贴给 DeepSeek。
  • 下一步：内置「整理提示词」模板——按主题聚类、按章节归并、提炼成读书笔记骨架，点一下就生成配好提示词的整段内容，复制即用；再做跨书主题聚合（把 N 本书的划线合起来问「这些书在同一个问题上怎么说」）。

2.5 生态连接：单机 → 你的自动化体系

  • 下一步：导出结果一键推到飞书（你已经在用飞书做文档协作）；接入 n8n 做后续流水线。

4架构：为什么这样分层

关键点：界面层与核心层彻底解耦。以后换界面（比如做手机端、做 Web 版）都不用碰抓取逻辑。

界面层
app_gui.py（PySide6 工作台）｜weread_hotmarks.py（CLI） 只负责展示与调度，不写任何抓取逻辑
核心层
core.py　搜索 / 抓取 / 渲染 / 导出 唯一真相源：改接口只改这一处，所有界面自动同步
模板层
template.py　HTML 模板（内联 CSS/JS） 卡片与复制文本同源于一份 JSON，永远一致
网络层
只读 GET · 不带 Cookie · 超时与异常统一包装 批量时叠加随机间隔，避免高频特征
存储层
exports/ 文件输出　→　（规划）SQLite 知识库 文件名带时间戳，永不覆盖既有成果

6风控与合规（批量后更要守）

事实层级内容
代码层可验证 只发 GET；不带任何 Cookie（默认请求器不含 Cookie 处理器）；无并发、无翻页循环；一次请求拿全书。服务端拿不到身份标识，技术上无法归因到账号，最坏情况是限 IP。
已验证该接口未登录即返回 200，本身不要求身份。
仍然存在的风险 这是非官方接口，平台协议通常禁止未经许可的自动化获取 —— 属条款层面风险，与「会不会封号」是两件事。
不确定平台风控的具体规则与是否使用额外识别手段，无内部信息，不做保证。

三条纪律（批量场景必须守）

  • 保留间隔：默认 2~4 秒随机，别调成 0 秒连发。
  • 别做公开服务：不要把它架成给他人用的网站或接口。
  • 别传播抓取结果：自用学习可以，公开批量分发不建议。

补充：桌面版默认走不带 Cookie 的通道（也就是风险最低的那条）；浏览器控制台版会带登录态，只建议偶尔手工用。

7技术选型：为什么是 PySide6

方案界面上限额外工具链打包 exe结论
PySide6高无（纯 pip）可以采用
本地 Web UI + 浏览器最高无较绕备选
Tauri 2.0 + Rust最高要装 Rust 工具链可以暂不

选它的三个理由：

  • 不用装任何额外工具链 —— 纯 pip，不占你紧张的 C 盘（虚拟环境已放在项目内的 D 盘）；
  • 能打包成独立 exe，符合「成熟软件」的形态；
  • 你另一个项目 scroll-extract 用的也是 PySide6 —— 学一次能改两个项目。
